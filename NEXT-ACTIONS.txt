================================================================================
                     OPERATIONAL RULE LEARNED TODAY - READ THIS
================================================================================

  After ANY change to odoo/addons/ggd_crm/** python, run:

        docker compose restart odoo

  Odoo does NOT re-import changed .py files when a module is upgraded. The
  registry reloads from modules already in sys.modules, and start-odoo.sh runs
  the server without --dev=reload. Passing tests therefore do NOT prove the
  live HTTP endpoint changed: the test run gets a fresh process, the running
  worker does not. Defect 13 below survived a correct fix for hours purely
  because of this.

                        DEFECTS FOUND (26-27 AUGUST)
================================================================================

11. THE ERROR WORKFLOW WAS ASSIGNED BUT NOT ACTIVE.  (26 Aug) FIXED.
    n8n refuses to run an inactive error workflow, so every failure in
    Workflows 01-05 went unrecorded. Assignment alone proves nothing.

12. THE SOURCE-URL GUARD REJECTED EVERY URL, VALID OR NOT.  (26 Aug) FIXED.
    n8n Code nodes run in a sandbox with no WHATWG URL global. The guard used
    it inside a try/catch, so the ReferenceError surfaced as "invalid public
    source URL" for every input. It failed shut, so nothing unsafe happened.
    Guard rewritten without the missing global, plus two sandbox-fidelity
    tests.

13. WORKFLOW 2 COULD NEVER STORE A DRAFT.  (26-27 Aug) FIXED, addon 19.0.1.7.0.
    ggd_prepare_draft returned a bare string, which Odoo serialises as a
    top-level JSON *string*. n8n's HTTP Request node parses the body once,
    sees the result is still a string, and parses it a second time -
    JSON.parse on raw hex throws. Every other addon method returns a dict,
    list, bool or int and never hits that second parse. The method now
    returns {"draft_version": "..."}.
    The fix appeared not to work for hours because the live Odoo worker was
    still running the old python. See the operational rule above.

14. CLEARING A DRAFT LEFT AN IMPOSSIBLE STATE.  (27 Aug) FIXED, addon 19.0.1.8.0.
    write() treats any draft-field change as an edit and forced
    ggd_draft_status = "ready". Clearing subject, body and version therefore
    produced status "ready" with no version - a lead that looks draft-ready
    with nothing to approve. New classifier _ggd_is_clearing_draft() handles
    the clear case; five regression tests added (103 -> 108).
    Not reachable from the six workflows; found while building test tooling.

15. A GATE 3 TEST PAYLOAD WOULD HAVE PASSED WITHOUT TESTING ANYTHING. (27 Aug)
    FIXED in scripts/gate3-workflow4-test-payloads.md.
    The unsubscribe scenario carried a timestamp older than the reply already
    stored on FX2. ggd_record_reply discards older replies, so the run would
    have gone green with nothing suppressed. Timestamp moved to
    2026-08-27T12:00:00Z. Re-check this if FX2 is ever reset.
